# ADR 0001 — OMR 대신 벡터 PDF를 직접 읽는다

- **상태**: 채택 (2026-07-31, `2380aa3`)
- **범위**: Phase 1 — 악보 PDF에서 음표 데이터 뽑기

## 결정

이미지 인식(OMR, Audiveris)을 쓰지 않는다. PDF 안의 글리프와 벡터 선을
좌표째로 읽어 구조를 복원한다.

## 맥락과 근거

당초 Audiveris로 OMR을 돌릴 계획이었으나, 실제 기타 악보 PDF를 조사한 결과
**OMR이 필요 없는 경우가 대부분**이라는 결론이 나왔다.

시중의 기타 악보 PDF는 대개 Guitar Pro·MuseScore에서 내보낸 **벡터 PDF**다.
조사한 샘플(Guitar Pro 내보내기, 12페이지)에서 다음이 전부 좌표와 함께
구조적으로 추출됐다.

| 필요한 정보 | PDF에서의 형태 | 추출 방법 |
|---|---|---|
| 프렛 번호 | 일반 텍스트 숫자 | 텍스트 + 좌표 |
| 현(string) | TAB 6줄 중 y 위치 | 줄 간격 6.4pt로 판정 |
| 음표 머리 | SMuFL 글리프 `U+E0A4` | 글리프 코드 |
| 데드 노트 | SMuFL 글리프 `U+E0A9` | 글리프 코드 |
| 쉼표 | `U+E4E3`~`U+E4E7` | 글리프 코드로 길이까지 |
| 임시표·점 | `U+E260`~`U+E262`, `U+E1E7` | 글리프 코드 |
| 플래그 | `U+E240`, `U+E241` | 글리프 코드 |
| 빔(beam) | 채워진 사각 폴리곤 | 겹친 개수로 음길이 판정 |
| 마디선 | 보표 높이의 세로선 | 선 길이로 판정 |
| 오선/TAB 구분 | 줄 5개 vs 6개 | 줄 간격(4.25 vs 6.38) |
| P.M., sl., 코드명 | 일반 텍스트 | 텍스트 + 좌표 |

폰트가 `GPBravuraRegular`, 즉 **SMuFL 표준 음악 폰트(Bravura)**라서
음악 기호가 표준 코드포인트를 가진 텍스트로 들어 있다. 이미지 인식이 아니라
파싱 문제라는 뜻이다.

이 경로가 OMR보다 나은 이유:

1. **정확도** — 좌표가 정확해서 인식 오류가 없다. OMR은 인쇄본 기준 85~95%다.
2. **TAB을 읽을 수 있다** — Audiveris는 오선보 전용이라 TAB을 아예 못 읽는다.
   기타 악보 PDF 상당수가 TAB인데, 벡터 추출은 TAB에서 현·프렛을 그대로 얻는다.
3. **운지 배정이 불필요** — Phase 2의 난제였던 "어느 줄 몇 프렛으로 칠지"를
   TAB이 이미 알려준다.
4. **의존성 없음** — Java 런타임과 Audiveris(AGPL) 번들이 필요 없다.

한계는 **스캔한 PDF·사진에는 안 통한다**는 것. 그건 Phase 1b로 미루고,
필요해지면 그때 OMR을 붙인다.
