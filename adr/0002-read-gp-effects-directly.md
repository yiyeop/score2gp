# ADR 0002 — GP 파일의 트랙 이펙터를 직접 파싱한다

- **상태**: 채택 (2026-08-02, `a841078`)
- **범위**: 읽기 모드 — 트랙별 이펙터 표시
- **구현**: `src/lib/gpEffects.ts`

## 결정

alphaTab이 버리는 이펙터 값(chorus/reverb/phaser/tremolo)을 얻으려고
GP 파일 헤더를 한 번 더 직접 훑는다.

## 맥락과 근거

GP3~GP5는 **chorus / reverb / phaser / tremolo** 값을 담는데 alphaTab의
데이터 모델(`PlaybackInformation`)에는 이 항목들이 없어서 파일을 읽는 순간
버려진다. 그래서 파일 바이트를 한 번 더 훑어 직접 꺼낸다
(`src/lib/gpEffects.ts`).

다만 실제 파일을 열어보니 애초 예상과 달랐다.

- **비트 단위 믹스 테이블에는 이펙터 값이 없었다.** 손에 있는 파일 두 종
  모두 0이었다. 그래서 타임라인은 이 경로로 나아지지 않는다 — 여전히 비트
  텍스트의 키워드에 기댄다(`src/lib/markers.ts`).
- **트랙 채널에는 값이 있었다.** 샘플 GP 파일 하나는 Guitar 3에 코러스
  128, 보컬에 리버브 24가 걸려 있다. 곡 내내 고정된 값이라 타임라인이 아니라
  트랙 목록에 어울린다 — "코러스 강하게"처럼 사람 말로 옮겨 보여준다.

채널 정보는 파일 앞쪽(마디·음표보다 먼저)에 있어서 헤더만 읽으면 닿는다.
버전마다 헤더 구성이 달라서(GP4에서 가사, GP5에서 RSE·페이지 설정이 추가됐다)
그 부분만 버전별로 갈라 따라간다. 마디와 음표는 alphaTab이 이미 읽으므로
건드리지 않는다.

트랙이 몇 번 채널을 쓰는지가 문제인데, alphaTab이 채널을 다시 배정해서
파일의 번호와 다르다(파일 8번 → alphaTab 16번). 관찰하면 두 배 관계지만
alphaTab 안쪽 사정이라 그대로 믿을 수 없어서, 짐작한 자리의 악기 번호가
트랙의 악기와 같은지 확인하고 어긋나면 아무것도 보여주지 않는다.
